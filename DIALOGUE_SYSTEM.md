# Общие диалоги в мире игры

`src/story/WorldDialogueSystem.js` — единственный владелец текста диалога, переключения реплик, камеры, виньетки и паузы боя. Презентация перенесена из рабочего диалога сюжетного рыцаря.

## Текущие взаимодействия

- `WoundedKnightInteractionSystem`: ищет ближайшего доступного рыцаря и запускает разговор по E (на телефоне — по тапу в правой половине экрана). Здесь остаются реплики рыцарей, маркер, условие открытия после третьей волны и завершение задания.
- `StoryEnemyAnomalySystem`: автоматически начинает разговор, когда выбранный аномальный скелет сближается с героем. Реплики находятся в `STORY_ANOMALY_DEFINITIONS` → `dialogue` в `src/story/storyEvents.js`.
- `ChampionDialogueSystem`: совместимый вход для сюжетных NPC/боссов, делегирующий разговор тому же общему модулю. После появления Broken Saint автоматически запускает пять исходных реплик; бой начинается после завершения разговора.

Одна клавиша без автоповтора или один клик/допустимый тап переключает одну реплику. Ввод открытия защищён задержкой 220 мс. Реплики не имеют таймера окончания. После последней реплики следующее нажатие закрывает разговор; камера возвращается, затем возобновляется бой. Аномальный скелет убегает только после завершения разговора.

## Подключить новый разговор

```js
const started = scene.dialogueSystem.begin({
  target: npc,                    // активный объект с x/y; для врага — объект врага
  initiator: 'npc',               // 'npc': внешний сюжетный/моб-триггер; 'hero': обработчик E
  owner: 'gateGuard',
  kind: 'npc',
  speakerName: 'Страж',
  eventId: 'gate_guard_first_talk',
  once: true,
  lines: [
    { speaker: 'npc', text: 'Стой. Куда направляешься?' },
    { speaker: 'hero', text: 'К часовне.' }
  ],
  onComplete: () => { /* реакция NPC / завершение задачи */ },
  onCancel: () => { /* отмена не отмечает eventId завершённым */ }
});
```

Инициатор задаёт источник запуска; проверка дистанции, E или сюжетного условия остаётся в клиенте взаимодействия. `begin` возвращает `false`, если цель недоступна, событие уже завершено, открыт другой разговор/меню или камера занята. Автоматический триггер должен сохранить состояние ожидания и повторить попытку позже — как у аномальных скелетов. Не запускайте таймер побега до `onComplete`.

`scene.dialogueSystem.cancel()` отменяет текущий разговор с восстановлением камеры и управления. Уничтожение цели, конец игры и остановка сцены также очищают диалог. Общие обработчики ввода устанавливаются до клиентов взаимодействия и удаляются при остановке сцены.

## Проверка

Все окна используют размещение из `WorldDialogueSystem`: предпочтительно над собеседником в центральной части экрана, с обходом обоих персонажей и видимого HUD. `HUDScene.getDialogueAvoidBounds()` отдаёт границы панелей, навыков, джойстика и полноэкранной кнопки в координатах canvas. Границы рисуемых Graphics сохраняются в `dialogueLocalBounds`; учитываются их текущие трансформации и видимость. Новую панель HUD следует зарегистрировать в этом методе.

Размещение пересчитывается перед отрисовкой, после обновления HUD и камеры. Размер текста и отступы компенсируют zoom и масштаб рендера. Если обычное окно не помещается, система ищет свободное место по границам препятствий, пробует более узкий перенос и затем меньший шрифт. `validate-dialogue-layout.mjs` проверяет геометрию на разных экранах и масштабах; измерение текста в нём заменено адаптером, поэтому это не визуальная проверка в браузере.

`npm run validate` проверяет проект, виньетку и поведение общего диалога: E, клавиатуру и тапы, все три аномалии, длительное ожидание, завершение задания, конфликты запусков, побег, отмену и очистку. Это проверки логики с адаптерами рендера, не визуальные браузерные тесты.

`npm run build` собирает игру.
